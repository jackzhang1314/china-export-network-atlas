## 客户先有采购问题，然后才会找到你


想象一位法国采购员需要定制硬盒。他可能先找供应商，再确认材料、尺寸、样品和交付。你的网站要陪他完成这段过程。

**教学示意 / 从采购需求到咨询**

采购需求 → 当地语言搜索 → 阅读合适页面 → 提出具体咨询。

每一步都需要相应的页面与信息支持。

### SEO 在这里做什么

SEO 是“搜索引擎优化”。通俗地说，就是让搜索引擎更容易理解你的页面，让有相关需求的买家有机会找到它。买家进入网站后，还需要清楚的产品资料与联系入口，才方便继续咨询。

### 网站要接住三句话

**我在找什么？** 用客户熟悉的产品名、用途与规格组织页面。

**你能不能提供？** 写清产品、制造能力、可选配置、交付与服务。

**怎样开始合作？** 让买家知道询价需提供什么，由谁回复。

> 图中是教学场景。先把“搜索 → 找到合适页面 → 了解产品 → 提出需求”的路径做好，再通过实际数据观察效果。

来源：[Google SEO 入门指南](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)


## 语言、当地内容和域名，分别帮买家解决什么？


以面向德国市场的定制包装站为例：买家需要读懂资料，找到适合自己的产品，也要知道你能够服务哪个市场。

**教学示意 / 三项工作的分工**

多语言解决谁能读懂；当地化解决怎样表达采购信息；国家域名说明面向哪个市场。

三项配合：覆盖语言、回答采购问题、明确服务市场。

### 多语言：让买家读得懂

把已确认的产品资料制作成德语、法语等版本。语言按采购人群选择：三一印度的 sany.in 使用英语，说明国家域名并不一定对应小语种。

### 当地内容：回答当地买家会问的问题

核对行业名称、常用规格、样品、报价资料和交付安排。同一产品的事实可以共用，各市场的服务说明分别确认。

### 国家域名：给市场一个清楚的入口

例如德国 .de、法国 .fr。一个国家站也可以有多种语言；注册前先核对后缀资格与名称可用性。

> 先选一个你能交付、有人回复的国家，把语言、产品和服务做到同一套真实页面上。

来源：[Google 多地区与多语言网站](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) · [三一印度](https://www.sany.in/)


## 国家域名的作用：把目标市场说清楚


网址末尾的 .de、.fr、.pl 等国家后缀，可以看作网站的市场标识。Google 将多数国家后缀视为明确面向相应国家的地域信号；专业名称是 ccTLD。

**教学示意 / 地域信号与经营工作**

.de 提供德国市场线索；产品内容、可信资料、网站可用性和持续运营共同支持业务。

国家后缀帮助表达面向的市场；具体排名由更多因素共同影响。

### 这对外贸业务有什么用

独立入口便于为每个国家安排主力产品、当地内容、报价负责人和统计。你的德国站可以围绕德国采购问题持续完善，法国站也有自己的内容计划。

### 要一起承担的工作

每个域名都需要注册与续费、稳定发布、内容维护和数据观察。国家后缀的注册资格各有要求；.eu 等后缀在 Google 中按通用域名处理。

### 怎样理解它与排名的关系

**地域信号帮助说明“服务哪里”，排名还取决于具体查询与页面表现。** 国家域名并不保证第一名，也不能代替产品内容、可信资料、网站可用性和长期运营。不同结构都可以做国际 SEO，本册选择国家域名作为你的实施主线。

来源：[Google 地域定位及网址结构说明](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)


## 网站上线后，搜索引擎还要认识你的页面


把网站发布到网上，只完成了“能够访问”。Google 还需要发现页面、理解内容，并在相关搜索发生时选择展示。

**教学示意 / 上线后的搜索过程**

发布让页面可以访问，抓取是读取页面，收录是纳入索引，展示是匹配相关查询。

各阶段分别检查；上线不代表已经收录，也不代表获得询盘。

### 把三个专业词换成日常话

**抓取：**搜索引擎访问页面，读取能够取得的文字、图片等信息。

**收录：**分析页面后，把它纳入自己的搜索索引。可以理解为进入可检索的资料库。

**搜索展示：**有人提出查询时，从索引中找相关结果。位置会随查询、语言、地区等情况变化。

### 你可以怎样配合

让首页和分类页能链接到产品；保持页面可访问；提供清楚的正文和站点地图；上线时检查是否仍有禁止收录的设置。技术人员或 AI 负责实现，你负责看产品和采购信息是否完整。

> 抓取、收录、展示与询盘是不同阶段。Google 不保证每个页面都会进入所有阶段；先查卡在哪一步，再安排相应工作。

来源：[Google 搜索的工作原理](https://developers.google.com/search/docs/fundamentals/how-search-works)


## 一份产品资料，支持多个国家站


先用一个国家站服务一个市场。产品资料整理清楚后，第二国可以沿用已经确认的型号、图片和页面设计，再补当地语言与服务说明。

**实施示意 / 共用资料，分别发布**

批准的产品资料与 AI 维护流程，支持德国 .de、法国 .fr、波兰 .pl 三个国家入口。

共用的是资料与组件；各国内容、正式域名和来源记录分别管理。

### 放在一起管理的资料

产品编号、材料、技术参数、图片和附件，以及真实的制造能力。参数变化时，先改这份共同资料，再找出需要更新的国家页面。

### 各国分别确认的内容

当地产品名称、主力型号、买家问题、交付条件、联系语言和报价负责人。当地仓库、经销商和服务点按实际业务填写。

### AI 可以帮你重复做，后台方便日常改

AI 协助建站、起草语言版本和批量更新。使用 WordPress 时，常改的产品与文章放进后台；少量修改可以自己完成，大批任务再交给 AI 协助。

> 先把首站的内容、收件和更新走通，再增加下一国。每站独立经营，不代表每站都要从零设计或单独租一台服务器。


## 先找到一个有能力服务好的国家


可以从已有询盘、成交客户或成熟经销渠道中选首站。已有业务线索能帮助你确定产品、术语、交付安排和回复方式。

| 判断项 | 需要拿出的材料 | 可以采用的动作 |
| --- | --- | --- |
| 有真实需求 | 历史询盘、客户问题、当地搜索样本 | 选择最常被问的一条产品线 |
| 能交付 | 出口条件、物流、交期与售后说明 | 写明能够承诺的服务范围 |
| 有内容基础 | 产品表、图片、说明书、案例 | 先做资料最完整的型号 |
| 有人承接 | 收件邮箱、回复语言、负责人 | 规定询盘到达后的处理方式 |
| 能持续维护 | 每月可投入时间与预算 | 确定更新频率和审核人 |

### 首站按一国一域推进

选择 **1 个国家、1 个国家域名、1 条主力产品线和 1 位负责人**。先把页面创建、当地内容、询盘投递与按域统计走通，再复制到下一国家。

### 域名注册前确认三件事

该后缀是否允许你的主体注册、名称是否可用、首次注册与后续续费条件是什么。资格受限时，先选能够合规注册且能服务的试点国家；资料未齐全时，先完成当地内容与产品清单。

> 在启动表里写一句话：“我们为【国家】的【采购人群】提供【产品】，由【负责人】承接【报价 / 样品 / 经销合作】。”能写清这句话，再进入建站。

## 同一种硬盒，进入不同语言的采购语境


Cajas Forradas 这组包装网站，用不同语言的产品相关词命名域名。法语站公开的语言版本声明，连接了下面五个入口。

### 这组案例适合看“怎样说”

比较当地网站怎样叫这类产品，使用什么分类、选项和询价表达。域名里的词提供了研究线索，真正的页面还需要说明材料、尺寸、工艺、样品和交付。

### 产品词域名与品牌域名怎样选

统一品牌便于长期识别；产品相关词可能更直观地表达业务范围。先考虑名称是否易记、是否符合你的长期产品线，并核对可用性。名称包含产品词，本身并不构成排名或询盘保证。

## 工业买家需要参数，也需要交付与服务答案

## 搜索结果里的几行字，要让买家知道你提供什么


买家还没进入网站时，会先看到搜索结果的标题、网址和摘要。它们需要清楚对应页面内容，也要符合该市场买家的语言。

**教学示意 / 虚拟搜索结果**

搜索结果由网址、标题和摘要构成；标题说清产品，摘要说明材料、定制与报价信息，正文兑现这些内容。

### 标题：说清产品与页面用途

例如，产品分类页可以说明产品类型、主要用途和真实的供应能力。用自然的当地语言写，避免把同义词和国家名挤成一长串。

### 摘要：给出继续阅读的理由

简洁说明页面能解答什么，例如可选材料、定制方式、报价需提供的资料。只有已经批准的事实，才写进标题与摘要。

标题说有尺寸和材料选项，页面里就应当找得到。Google 可能根据查询和页面内容调整标题或摘要，所以要同时把页面正文写清楚。

## 一个好产品页，帮助买家完成一次判断


用定制硬盒举例。页面既要让搜索引擎理解产品主题，也要让买家知道能否继续询价。下面是教学布局，可按你的产品调整。

**教学示意 / 定制硬盒产品页结构**

产品页先展示产品身份和真实图片，再提供材料规格、工艺证据、合作流程及询价入口。

图中只有内容结构，未预设真实规格、认证、最低起订量或交期。

### 先回答选型问题，再解释合作流程

买家需要看到产品是什么、有哪些材料和配置、适合什么用途。随后确认制造能力、样品、交付与报价所需信息。参数没有确认时，进入待补清单。

### 图片与技术资料也要能说明问题

使用真实产品和工艺照片，写清图片对应的型号或选项；下载资料标明版本。重要参数应以页面文字呈现，方便阅读与核对。

## 内链就是网站里的路标：从问题走到产品


“内链”指同一网站页面之间的链接。它帮助买家继续阅读，也帮助搜索引擎发现页面、理解相关内容。

**教学示意 / 内链把采购问题连到产品**

采购指南连接相关分类与产品，产品提供资料下载和询价入口。

每个国家站都应有自己的清晰路径；链接文字说明下一页能看到什么。

### 从一个采购问题开始

例如“怎样选择硬盒内托”，可以写成采购指南。指南解释选择依据，再链接到相关盒型、材料选项和产品；买家可继续查资料或询价。

### 链接文字写出目的地

“查看磁吸硬盒的材料选项”比反复写“点击这里”更清楚。分类页应能到达具体产品，产品页也可以连接相应用途、指南和服务说明。

### 把销售经验存进网站

PROFISHOP 用专业指南连接商品。你的销售答复也可以整理成选型文章，在 WordPress 后台存为草稿、核对后发布，并链接到相应产品。以后客户问了新问题，再回到原文补充。

> 后台方便团队持续整理内容；文章是否有用、能否带来搜索访问，要结合客户需求和实际反馈判断。

## 让客户信任你，需要可核对的资料与真实联系


当地语言让信息更容易理解，真实资料帮助买家判断是否值得继续沟通。可以从网站内外两个方向积累这些依据。

**教学示意 / 网站内外的可信资料**

网站内展示产品事实、公司与交付证据；网站外通过相关行业、客户或伙伴的真实引用帮助买家核对。

自家国家站的版本切换属于导航；独立行业来源的引用需要分别识别。

### 网站内部：把能力说明具体

展示真实公司身份、产品参数、制造流程、证书适用范围、交付和服务安排。能够公开的案例，要说明产品与使用场景。没有当地仓库或实体，就如实介绍自己的出口与服务方式。

### 网站外部：让有用资料被发现与引用

“外链”指其他网站链接到你。相关客户、合作伙伴、协会或行业媒体可能引用你的产品资料、技术说明或案例。优先建设真正有用、方便核对的资料，再通过正常业务交流让人知道它。

### 看清自家互链与外部引用的区别

自家国家站之间的切换，主要帮助用户找到对应版本。它与独立机构的行业引用是不同关系。Jongen 的历史外链分析就提醒读者区分集团网站与独立来源。

## 两个技术标记：首选地址与对应语言版本


你不需要背代码。先看懂下面的关系，再让执行人员或 AI 说明每个页面怎样设置。

**教学示意 / 同一产品的跨国版本**

德国产品页声明自己的首选网址，法国产品页也声明自己；两页的 hreflang 表同时列出自身与对方。

网址为结构示意；独立当地页的首选地址与跨国版本表承担不同职责。

### canonical：这份内容优先使用哪个网址

可以把它理解为“首选地址说明”。可独立收录的当地产品页通常声明自己的网址；同语种、内容高度相近的重复网址，需要结合实际内容确定首选版本。它是信号，Google 仍可能选择其他规范网址。

### hreflang：还有哪些对应语言或地区版本

可以把它理解为“版本对照表”。同款产品的德国页与法国页相互对应，并把自己也列进去。这种关系可以跨域，执行时可通过页面代码、响应头或站点地图维护。

### 你能做的检查

打开一个产品的德语页，切换到法国版本，确认仍是同款或实际对应产品。让 AI 列出两页的首选地址与版本对照表，检查是否指错产品或统一指回首页。

> 图为虚拟网址示意。语言切换帮助人浏览，版本标记帮助搜索引擎理解关系；标记本身不保证排名或收录。

## AI 先整理，人来核对最影响采购的地方


AI 可以根据产品资料整理结构、起草不同语言的页面。是否能够发布，要看买家读到的参数、行业用词和服务承诺是否准确。

**实施示意 / 从批准资料到可发布页面**

批准资料 → AI 整理与起草 → 产品和目标语审核 → 发布有用的当地页面。

每个国家页都要能独立帮助买家了解产品并提出需求。

### 先核事实，再核当地表达

业务人员核对型号、数值、单位、图片、认证范围、起订量与交期。懂产品和目标语言的人，再核对行业名称、选型说法和表单提示。

### 不懂目标语言，也要能核对业务内容

让 AI 同时输出目标语和中文核对版，并标出资料里没有依据的内容。中文版本方便核事实，目标语仍需结合客户用词和行业资料检查。确认过的名称放进术语表，下次继续使用。

### 每个国家页都回答真实问题

买家应当能在当前站查产品、了解交付、知道报价要提供什么。只换国家名、堆出大量内容相近的薄弱页面，不能替代这些信息，也可能涉及 Google 的门页或规模化内容问题。

> 第一批页面把资料、术语和审核意见留下来。以后新产品沿用已确认部分，再补各国实际差异。

来源：[Google 对生成式 AI 内容的说明](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content) · [Google 内容垃圾政策](https://developers.google.com/search/docs/essentials/spam-policies)


## 老板、SOHO、外贸公司，后台分别帮在哪里？


网站上线后，最常发生的是换图片、改参数、上新品和回答客户问题。WordPress 的后台，相当于给这些内容准备了一套可以反复打开编辑的表单。

**日常场景 / 三类读者怎样使用后台**

工厂老板把日常修改交给同事；SOHO 自己完成少量更新；外贸公司用产品编号对齐不同供应商的资料。

工作方式示意；常改内容需要在建站时安排好编辑入口。

### 工厂老板：让同事接得住日常维护

例如工厂换了产品包装，业务员可以进入对应产品，更新图片和说明；负责人核对事实后再发布。常改内容有固定入口，交接时能说清“这项去哪里改、谁来确认”。

### SOHO：小改动可以随手做

客户问了一个产品页没写清的问题，你可以打开产品，补一条常见问题；也可以新建文章草稿，把经验慢慢补齐。一次要整理很多产品时，再让 AI 协助。

### 外贸公司：不同供应商的资料容易找回

例如两家供应商都有相似型号，先给自家目录安排不同产品编号，再关联各自参数、图片和附件。网站按统一格式展示，同事接手时能对回正确资料。内部供应商备注另行保存，按公开范围发布。

> 这些便利有一个前提：建站时把常改内容做成可编辑项。交付时亲手试改、保存、查看前台，比只看首页更能判断是否好用。


## 改一张产品图，可以像填表一样完成


以定制硬盒为例。买家看到的是排版好的产品页；你在后台看到的是名称、图片、参数和说明。新增同类产品时，继续使用已有样式。

**编辑示意 / 后台栏目与产品页对应**

产品名称、图片、参数、详情、常见问题和关联产品在后台分别编辑；前台模板将它们组织成产品展示与询价页面。

按产品编辑方式绘制的示意图；实际栏目与样式按网站设计。

### 试着走一遍日常修改

打开“产品”栏目 → 找到产品编号 → 换图或改参数 → 保存并重新打开 → 查看买家看到的页面。

### 需要批量处理时，让 AI 沿用现有栏目

把确认过的产品表交给 Codex，先核对网站已有内容，再按同样的编辑项制作草稿。检查型号、图片和分类对应后，分批发布。

### 内容更新与改版，工作量不同

已有栏目里的内容可以直接维护。增加全新页面布局或新的参数栏目，仍需要调整网站设计。用 WordPress Builder Harness 建站时，要把今后常改的内容一起安排好。

> 可以当场试三个动作：换一张图片、改一项参数、新建一个产品草稿。都能顺利完成，才说明这套后台适合日常使用。


## 同事能编辑，老板也能把握发布内容


团队可以把准备资料、审核和发布交给不同的人。一个人经营时，也可以先存草稿，等资料齐全后再发布。

**协作示意 / 新内容从草稿到发布**

AI 或编辑准备草稿，业务负责人核事实，目标语审核人核表达，具有权限的人发布并检查。

角色和权限按本站配置；已发布内容的修改另行核对影响。

### 新内容先放草稿

例如业务员根据产品表准备页面，负责人核对参数、起订量与交期，懂目标语言的人复核表达，再由有发布权限的人上线。这样，待确认内容有地方放，工作也方便接续。

### 每个人使用自己的账号

WordPress 可以按职责配置编辑、发布或管理权限。交付时，用业务员的实际账号试一下：该改的产品能否编辑、哪些内容需要负责人发布。特殊产品栏目按本站设置核对。

### 改错时要知道怎样找回

文章修订可帮助查历史；产品参数、图片和整站内容的恢复范围需要另外检查。重要修改先预览，并保留网站备份。发布过的页面直接点“更新”，可能马上影响前台。

> 草稿和权限是协作基础；若团队需要“提交后必须由老板批准”，应在建站时明确提出并实际验证。

## 第二个国家站，复用资料，再确认市场差异


例如德国、法国和波兰分别建立自己的 WordPress 站。首站做好后，产品资料、页面设计和编辑方法可以复用，各国内容与负责人分别安排。

**实施方案 / 共用资料，各国独立维护**

共用批准资料、术语和设计规范，德国、法国、波兰分别使用独立 WordPress 站；各国保留当地内容、收件负责人和发布记录。

不假定一个总后台自动同步全部网站；按项目分别更新与检查。

### 产品相同，承诺可能不同

型号、图片和已确认参数可以共用；主推产品、配置、交期、联系语言和售后范围按市场核对。用产品编号记录各国对应页面，方便以后一起查找。

### 同事已经改过的内容，要先读再更新

让 AI 查看网站现有记录，比较新产品资料，只改本次确认的部分。早期建站文件可能已过时，整套重新导入会覆盖后来编辑的内容。

### 首站练熟，再扩大维护范围

先完成一次产品更新、一次文章发布和一次询盘测试，再做第二国。每站都有自己的后台与记录；共用资料不等于一个总后台自动同步所有网站。

> 判断能否扩站，可以看自己能否答出：每国谁更新、谁审核、谁收件，以及参数变化时怎样找到对应页面。


## 选哪条路线，先看日后谁来更新


如果准备持续增加产品、文章和案例，并让业务人员参与编辑，建议把 WordPress 用作长期经营的主力国家站。内容较稳定、更新集中交给 AI 处理时，静态站也可以持续使用。

| --- | --- | --- |
| 改图、改参数 | 打开对应内容，在后台编辑 | 让 AI 修改文件，检查后重新发布 |
| 新增同类产品 | 填写已有栏目，复用页面样式 | 按现有资料格式新增并生成网页 |

### 按自己的工作来选

**产品经常变、同事要参与、准备持续写内容：**优先 WordPress。后台的价值，是让这些日常动作有清楚的入口。

**范围清楚、内容稳定、由自己和 AI 集中维护：**可以用赠送的静态站 Skill 起步。它也适合独立产品专题或新市场试点。

> 可以直接从 WordPress 开始，也可以一直使用合适的静态方案。两者都能做 SEO；实际效果要看页面内容、搜索需求和持续经营。

| 询盘承接 | 邮箱、国家、域名、产品编号 | 实际邮件能看出来自哪一站 |
| 搜索记录 | 每域 Search Console 与统计 | 分开观察搜索与有效页面 |
| 资产与恢复 | 域名到期、账号、备份负责人 | 可持续续费、交接与恢复 |

### 先完成一国，再复用到下一国

复用已确认的产品字段、页面设计和术语。第二国的语言、主力产品、交付、联系方式与服务范围重新确认，各自发布与检查。

### 语言切换连接对应页面

买家从德国产品切换到法国版本时，应进入法国域名上的同款或实际对应页面。暂时没有对应版本，就明确展示可用市场入口。

> 域名绑定、当地正文、后台维护和询盘承接一起完成，才形成可以使用的国家站。随包配置表不保存账号密码。

## 建站前，把资料整理成可以复用的输入


| 资料 | 至少准备什么 | 使用方式 |
| --- | --- | --- |

| 产品主表 | 编号、型号、参数、单位、选项、图片文件名 | 生成分类、产品与参数模块 |

### 给产品一个稳定编号

例如 BOX-001、PUMP-002。编号用于内部追踪，不必成为对外商品名。每个国家页记录同一编号，方便批量改动与检查。

### 把未知项写出来

资料没有的认证、当地仓库、交期、客户名单和性能数据，标成“待确认”。AI 可以帮助列问题；发布内容必须使用已确认事实。

### 区分批准资料与网站当前内容

公司资料、产品主表、图片、附件和术语表保存共同事实。WordPress 后台保存网站实际内容；更新前先读取并核对，避免旧文件覆盖同事的新修改。静态站按项目指定的内容文件维护。

> 随包提供首站、产品语言、竞品、维护、询盘和国家域名发布等表格。用普通表格软件即可填写。

常见必要信息是联系人、邮箱和需求描述。产品型号、数量、目标国家、尺寸或图纸，可按产品场景设置。字段越复杂，越要解释为什么需要。

### 产品页尽量自动带出上下文

让买家从某产品页点击询价时，表单已经带上产品编号、页面网址与语言。业务员收到邮件后能直接知道对方在看什么。

## 首站验收：能阅读、能修改、能实际收件


第一次做网站，把“完成”写成几个能亲手检查的动作。前台、后台与询盘都能工作，才能放心交给团队接着维护。

**实施示意 / 首站的三个验收结果**

检查前台内容和正式网址；验证后台编辑或静态更新发布；提交测试询盘并核对保存与实际收件。

用正式域名检查实际输出；编辑、保存与收件分别记录结果。

### 前台内容与正式网址可用

产品事实、图片与附件正确，手机和电脑可以阅读。国家域名的首页、分类和产品页能打开，语言、首选网址、站点地图与切换关系对应正式站。

### 内容确实可以继续维护

WordPress：在后台改一个产品参数、保存重开，核对前台；再新增一篇草稿并预览。静态站：修改一处内容、重新生成并发布，确认正式页面生效。

### 咨询确实可以到达

从产品页提交一条标记清楚的测试询盘，核对保存记录和实际收件，检查回复地址、域名、产品与页面来源。失败时能发现问题并找到负责人。

> 使用随包“首站实操验收表”登记结果。测试证明的是此次路径；正式运营继续观察。保存网站、内容、配置与恢复资料，便于接着更新。

| 网站托管 | 主机、数据库、资源与备份 | 静态托管有免费方案；表单等另按额度 |

### 用自己的任务判断后台是否值得

一个主机套餐可能容纳多个 WordPress 站，也有站点数和资源限制；静态托管与外部服务有各自额度。扩到第二国前，核对实际套餐、备份和维护安排。

**实施示意 / 一次产品变化的维护闭环**

| --- | --- | --- |

| 扩站前 | 复查模板、后台字段、表单与语言 | 可复用版本与新市场差异 |

### 两种更新路径，遵循同一份批准资料

WordPress 更新对应内容记录；静态站修改相应内容文件并重新发布。AI 根据实际网站结构执行，分别核对结果，市场专属交付与联系信息继续保留。

### 把恢复方式留下来

记录这次改了什么、谁审核、什么时候发布。WordPress 的内容备份与代码版本分别保存；静态站保留源码和发布版本，询盘等服务数据另行管理。


## 看懂五层数据，才知道下一步该改哪里


Google Search Console 是查看自然搜索表现的工具；询盘与报价进展则需要表单记录和销售补充。两类信息放在一起，才便于判断业务价值。

**教学示意 / 从搜索表现到销售推进**

搜索曝光 → 搜索点击 → 收到咨询 → 判定有效询盘 → 报价或样品推进；前两层由搜索工具观察，后三层由表单与销售记录。

层级形状只表示流程，不表示人数、转化率或各阶段的真实比例。

### 曝光、点击和有效询盘怎样区分

**曝光：**网站出现在搜索结果中。**点击：**用户从搜索结果点击进入。点击率等于点击数除以曝光数。**有效询盘：**由销售根据产品匹配、需求与联系信息判断。

### 每个国家分别看，再看趋势

记录国家域名、页面、查询词、目标地区和日期。把包含自己品牌名的搜索，与产品或采购问题的非品牌搜索分开观察。测试、垃圾和重复询盘单列。

### 从问题反推行动

有曝光但少人点击，检查搜索意图与标题；有访问但缺少咨询，检查产品信息、联系方式和需求匹配；有询盘但难推进，结合销售反馈核对交付与客户质量。

> 图中没有预设转化率。用随包月度表记录自己的结果，结合季节、广告和业务变化判断，再决定是否扩展下一国。

## 读案例时，分清国家域名与其他网址结构


本册主推国家域名方案。研究大型企业时仍会遇到区域 .com、语言目录与子域，把这些结构识别清楚，才不会把它们全部统计成独立国家域名。

| 架构 | 真实样本 | 适合解决的问题 | 需要承担的维护 |
| --- | --- | --- | --- |
| 独立国家域名 | sany.in；igus.pl | 明确的当地业务入口 | 每域发布、监测、续费和资料同步 |

| 语言或地区子域 | fr.yutong.com | 分团队或分系统运营 | 子域配置与版本管理 |

### 国家市场与页面语言分别记录

三一印度的 sany.in 使用英语；一个国家也可能需要多种语言。国家域名确定面向哪个市场，页面语言再按该市场的采购人群安排。三一全球站的语言目录适合参考资料管理方式。

### 还要确认最后打开的页面

有些历史国家域名会跳转到统一网站，例如 Picodi 的旧域名进入 .com 对应目录。观察竞品时，继续打开产品深页，记下最终网址。带国家名称的 .com，以及 Google 按通用域名处理的 .eu，不能直接计作国家后缀样本。

## 术语速查：知道它在工作里指什么


遇到术语时，可以回到这张表。需要具体配置，再让 AI 或执行人员结合你的网站解释。

| 术语 | 通俗解释 |
| --- | --- |
| SEO | 帮助搜索引擎理解网站，让相关买家有机会从搜索中找到页面。 |
| 关键词 / 搜索意图 | 买家输入的词，以及这次搜索想完成的事情。 |
| 域名 / URL | 网站地址的核心部分；某个具体页面的完整网址。 |
| 国家域名 / ccTLD | 带国家后缀的域名。多数能表达对应市场，部分后缀按通用域名处理。 |
| WordPress / 后台 | 保存和编辑产品、文章、图片与页面的系统。 |
| Codex / Harness | 本册使用的 AI 协作工具，以及配套的建站工具与操作方法。 |
| 静态站 / Skill | 生成为网页文件后发布的网站；指导 AI 完成某类任务的规则与资料。 |
| 抓取 / 收录 | 搜索引擎访问读取页面；分析后把页面纳入搜索索引。 |
| canonical | 页面建议采用的首选网址，帮助处理重复或相近网址。 |
| hreflang | 告诉搜索引擎哪些页面是对应的语言或地区版本。 |
| 站点地图 / sitemap | 供搜索引擎发现页面的网址清单。 |
| 内链 / 外链 | 本网站页面之间的链接；其他网站指向你网站的链接。 |
| 曝光 / 点击 / 点击率 | 搜索结果中展示、被点击，以及点击数占曝光数的比例。 |
| Search Console | Google 提供的搜索表现与收录排查工具。 |
| MOQ / RFQ | 最低起订量；买家提交的询价请求。 |

> 实际工作时，重点分清：网站能打开、已被收录、获得点击、收到有效询盘。这几件事需要分别观察。

来源：[Google SEO 入门](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) · [WordPress 功能](https://wordpress.org/about/features/)


## 怎样继续查案例与来源


### 打开同业网站，重点看五件事

1. 从品牌或厂家官方目录进入当地站，记下最后打开的网址。
2. 找到同一产品或相似用途，比较两个市场的页面与附件。
3. 查看公司、联系、交付与售后说明，确认谁在承接业务。
4. 试着走一遍分类、产品、语言切换和询价入口。
5. 把看到的事实、尚未证实的推断、自己想采用的做法分别记录。
